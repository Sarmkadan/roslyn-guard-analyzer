# CodeFix

`CodeFix` represents a single automated code correction generated by the Roslyn guard analyzer. It encapsulates the diagnostic that triggered the fix, the original and replacement source text, location metadata, severity classification, and the outcome of applying the fix. Instances are produced during analysis runs and can be chained through the `AppliedFixes` and `FailedFixes` collections to track multi-step remediation attempts.

## API

### Constructors

- **`CodeFix()`**  
  Initializes a new, empty instance of `CodeFix`. All string properties default to `null` or empty, numeric properties to zero, `Severity` to its default value, `GeneratedAt` to `DateTime.MinValue`, `IsBreakingChange` to `false`, and the fix lists and message list to empty collections.

### Properties

- **`string Id`**  
  A unique identifier for this specific fix instance. Typically a GUID or a deterministic hash derived from the violation and location.

- **`string ViolationId`**  
  The identifier of the specific violation pattern detected. This is more granular than `RuleId` and distinguishes between different ways the same rule can be triggered.

- **`string RuleId`**  
  The identifier of the analyzer rule that produced the diagnostic (e.g., `"GUARD001"`). Multiple `CodeFix` instances may share the same `RuleId` but differ in `ViolationId`.

- **`string Title`**  
  A short, human-readable label for the fix, suitable for display in IDE lightbulb menus or diagnostic reports.

- **`string Description`**  
  A longer explanation of what the fix changes and why. May include before/after narratives or links to documentation.

- **`string FilePath`**  
  The absolute or relative path to the source file containing the code to be fixed.

- **`int StartLine`**  
  The one-based line number where the original code region begins.

- **`int EndLine`**  
  The one-based line number where the original code region ends. Must be greater than or equal to `StartLine`.

- **`string OriginalCode`**  
  The exact source text extracted from the document before the fix is applied.

- **`string ReplacementCode`**  
  The source text that will replace `OriginalCode` when the fix is applied.

- **`SeverityLevel Severity`**  
  The severity classification of the underlying diagnostic (e.g., Error, Warning, Info, Hidden). Influences whether the fix is applied automatically or requires user confirmation.

- **`DateTime GeneratedAt`**  
  The UTC timestamp when this `CodeFix` instance was created.

- **`bool IsBreakingChange`**  
  Indicates whether applying this fix may alter the public API surface or runtime behavior in a way that could break dependent code. When `true`, the fix should be reviewed carefully before application.

- **`bool IsValid`**  
  Returns `true` if the fix has all required fields populated and passes internal consistency checks (e.g., non-empty `Id`, valid line range, `OriginalCode` not equal to `ReplacementCode`). An invalid fix should not be applied.

- **`bool IsSuccess`**  
  Indicates whether this specific fix was applied successfully. Set after an application attempt; remains `false` until explicitly updated by the fix engine.

- **`List<CodeFix> AppliedFixes`**  
  A collection of child fixes that were successfully applied as a consequence of applying this fix. Allows tracking of cascading or multi-step corrections.

- **`List<CodeFix> FailedFixes`**  
  A collection of child fixes that failed during application. Useful for diagnostics and reporting partial success scenarios.

- **`List<string> Messages`**  
  Diagnostic messages, warnings, or informational entries accumulated during fix generation or application. May contain compiler errors, transformation logs, or validation results.

### Methods

- **`string GetSummary()`**  
  Returns a formatted single-line summary of the fix, typically combining `RuleId`, `Title`, `FilePath`, and line range. Takes no parameters. Never throws; returns an empty string if critical properties are null.

## Usage

### Example 1: Inspecting a Generated Fix

```csharp
CodeFix fix = analyzer.GenerateFix(diagnostic);

if (fix.IsValid)
{
    Console.WriteLine(fix.GetSummary());
    Console.WriteLine($"Severity: {fix.Severity}");
    Console.WriteLine($"Breaking change: {fix.IsBreakingChange}");

    if (fix.IsBreakingChange)
    {
        Console.WriteLine("Manual review required before application.");
    }

    Console.WriteLine("Original:");
    Console.WriteLine(fix.OriginalCode);
    Console.WriteLine("Replacement:");
    Console.WriteLine(fix.ReplacementCode);
}
else
{
    foreach (string message in fix.Messages)
    {
        Console.WriteLine($"Validation error: {message}");
    }
}
```

### Example 2: Applying a Fix and Handling Cascading Results

```csharp
CodeFix rootFix = engine.GetFixForViolation(violationId);
bool applied = engine.TryApplyFix(rootFix);

if (rootFix.IsSuccess)
{
    Console.WriteLine($"Root fix applied: {rootFix.Title}");

    foreach (CodeFix cascadingFix in rootFix.AppliedFixes)
    {
        Console.WriteLine($"  Cascading fix applied: {cascadingFix.Title} at line {cascadingFix.StartLine}");
    }

    foreach (CodeFix failedFix in rootFix.FailedFixes)
    {
        Console.WriteLine($"  Cascading fix FAILED: {failedFix.Title}");
        foreach (string msg in failedFix.Messages)
        {
            Console.WriteLine($"    Reason: {msg}");
        }
    }
}
else
{
    Console.WriteLine($"Root fix failed: {rootFix.Title}");
    foreach (string msg in rootFix.Messages)
    {
        Console.WriteLine($"  {msg}");
    }
}
```

## Notes

- **Validity before application:** Always check `IsValid` before calling any application logic. An invalid fix typically has an empty `Id`, `OriginalCode` identical to `ReplacementCode`, or `StartLine` greater than `EndLine`. The `Messages` list will contain specific validation failures.

- **Line numbering:** `StartLine` and `EndLine` are one-based. If the analyzer operates on zero-based line indices internally, conversion must occur before populating these properties.

- **Cascading fixes:** The `AppliedFixes` and `FailedFixes` lists are populated only after an application attempt. They are empty for freshly generated fixes. Do not assume they contain entries until `IsSuccess` has been set.

- **Thread safety:** `CodeFix` is not thread-safe by design. Instances are intended to be created, validated, and applied within a single synchronization context. Concurrent reads of `Messages`, `AppliedFixes`, or `FailedFixes` while another thread is applying the fix may result in enumeration exceptions or inconsistent state.

- **`IsBreakingChange` semantics:** This flag is a heuristic set by the analyzer. A value of `false` does not guarantee zero behavioral impact; it indicates the analyzer did not detect API surface changes. Manual review is recommended for fixes in public APIs regardless of this flag.

- **`GetSummary()` format:** The exact format is implementation-defined and may change across versions. Do not parse it programmatically; use the individual properties for structured data access.
