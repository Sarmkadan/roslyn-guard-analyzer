# SarifFormatter

The `SarifFormatter` type provides a convenient way to serialize analyzer findings into the SARIF (Static Analysis Results Interchange Format) JSON structure. It exposes the constituent parts of a SARIF log as properties, allowing callers to populate the model and then retrieve formatted strings for individual results, violations, or the complete report.

## API

| Member | Type | Description |
|--------|------|-------------|
| `FormatResult` | `string` | Gets or sets the SARIF‑formatted representation of a single analysis result. Typically populated after invoking a formatting method; returns `null` if no result has been formatted. |
| `FormatViolations` | `string` | Gets or sets the SARIF‑formatted representation of all violation collections. Returns a JSON string containing the `results` array; `null` when no violations have been processed. |
| `FormatReport` | `string` | Gets or sets the complete SARIF log as a JSON string, including `runs`, `tool`, `invocation`, and other top‑level sections. Returns `null` if the formatter has not been initialized with sufficient data. |
| `CanFormat` | `bool` | Indicates whether the current state of the formatter contains enough information to produce a valid SARIF output. Returns `false` when required collections (e.g., `Runs` or `Tool`) are empty or `null`. |
| `Version` | `string` | The SARIF schema version targeted by the formatter (e.g., `"2.1.0"`). Setting this value influences the JSON structure generated by `FormatReport`. |
| `Schema` | `string` | The URI of the SARIF JSON schema used for validation (e.g., `"https://schemastore.azurewebsites.net/schemas/json/sarif-2.1.0.json"`). |
| `Runs` | `List<SarifRun>` | Collection of `SarifRun` objects representing each analysis run. Each run contains its own tool, invocations, and results. |
| `Tool` | `SarifTool` | Describes the tool that produced the log (e.g., the analyzer package). Includes properties such as `Name`, `Version`, and `InformationUri`. |
| `Invocations` | `List<SarifInvocation>` | List of invocation details, capturing command‑line arguments, execution time, and other runtime information for each run. |
| `Results` | `List<SarifResult>` | Flat list of all `SarifResult` objects across all runs. Each result encodes a specific violation, its location, severity, and associated rule. |
| `ColumnKind` | `string` | Specifies how column numbers are interpreted in the SARIF log (e.g., `"utf16"` or `"utf8"`). Must match the column numbering used by the analyzer. |
| `Driver` | `SarifToolDriver` | The driver component of the tool, often representing the executable or SDK that launched the analysis. |
| `Name` | `string` | The display name of the tool (first occurrence). Used in the `tool.driver.name` field of the SARIF log. |
| `InformationUri` | `Uri?` | A URI pointing to documentation or further information about the tool. May be `null` if no such information is available. |
| `Version` | `string` | The version of the analyzer or rule set being reported (second occurrence). Distinguishes the analyzer version from the SARIF schema version. |
| `Rules` | `List<SarifRule>` | Collection of `SarifRule` objects that define the rules checked during analysis. Each rule includes an `id`, `name`, `shortDescription`, and optional `helpUri`. |
| `Id` | `string` | The identifier of the tool or rule set (context‑dependent). In the SARIF model this often maps to `tool.driver.id`. |
| `Name` | `string` | The name of the rule or tool component (second occurrence). When associated with a `SarifRule`, this corresponds to the rule’s friendly name. |
| `ShortDescription` | `SarifMessage` | A brief textual description of the result or rule, suitable for display in summaries. |
| `HelpUri` | `string?` | A URI linking to detailed help or documentation for a specific rule. May be `null` if no help is available. |

*All members are simple get/set auto‑properties; they do not throw exceptions under normal use. Attempting to read a property before assigning a value returns the default for its type (`null` for reference types, `0` for numeric types, `false` for `bool`).*

## Usage

### Basic report generation

```csharp
using RoslynGuardAnalyzer.Sarif;
using System.Collections.Generic;

// Create the formatter and populate required sections.
var formatter = new SarifFormatter
{
    Version = "2.1.0",
    Schema = "https://schemastore.azurewebsites.net/schemas/json/sarif-2.1.0.json",
    CanFormat = true   // will be true once Runs and Tool are set
};

formatter.Tool = new SarifTool
{
    Name = "Roslyn Guard Analyzer",
    Version = "1.2.3",
    InformationUri = new Uri("https://github.com/roslyn-guard-analyzer")
};

formatter.Driver = new SarifToolDriver
{
    Name = "RoslynGuard",
    Version = "1.2.3",
    InformationUri = formatter.Tool.InformationUri
};

formatter.Runs = new List<SarifRun>
{
    new SarifRun
    {
        Tool = formatter.Tool,
        Invocations = new List<SarifInvocation>
        {
            new SarifInvocation { ExecutionSuccessful = true }
        },
        Results = new List<SarifResult>
        {
            new SarifResult
            {
                RuleId = "RG001",
                RuleIndex = 0,
                Message = new SarifMessage { Text = "Possible null reference dereference." },
                Locations = new List<SarifLocation>
                {
                    new SarifLocation
                    {
                        PhysicalLocation = new SarifPhysicalLocation
                        {
                            ArtifactLocation = new SarifArtifactLocation { Uri = new Uri("file:///src/Program.cs") },
                            Region = new SarifRegion { StartLine = 12, StartColumn = 5, EndColumn = 5 }
                        }
                    }
                }
            }
        }
    }
};

formatter.Rules = new List<SarifRule>
{
    new SarifRule
    {
        Id = "RG001",
        ShortDescription = new SarifMessage { Text = "Null reference detection" },
        HelpUri = "https://github.com/roslyn-guard-analyzer/docs/rules/RG001"
    }
};

// Produce the final SARIF log.
string sarifJson = formatter.FormatReport;
System.IO.File.WriteAllText("roslyn-guard.sarif", sarifJson);
```

### Formatting a single result for logging

```csharp
var formatter = new SarifFormatter
{
    ColumnKind = "utf8"
};

var result = new SarifResult
{
    RuleId = "RG002",
    Message = new SarifMessage { Text = "Unused using directive detected." },
    Locations = new List<SarifLocation>
    {
        new SarifLocation
        {
            PhysicalLocation = new SarifPhysicalLocation
            {
                ArtifactLocation = new SarifArtifactLocation { Uri = new Uri("file:///src/Utils.cs") },
                Region = new SarifRegion { StartLine = 3, StartColumn = 1, EndColumn = 1 }
            }
        }
    }
};

formatter.Results = new List<SarifResult> { result };
string resultJson = formatter.FormatResult;
// resultJson can be appended to a log file or sent to a telemetry sink.
```

## Notes

- **Property ordering matters**: The type contains two properties named `Version` and two named `Name`. The first `Version` corresponds to the SARIF schema version, while the second reflects the analyzer/rule set version. Likewise, the first `Name` is the tool’s display name; the second is used for rule or driver naming depending on context. Setting the wrong property may produce SARIF output that validates against the schema but contains semantically incorrect fields.
- **Nullability**: Reference‑type properties (`InformationUri`, `HelpUri`, collections, etc.) accept `null`. Consumers should verify that required data is non‑null before calling formatting methods; otherwise the resulting JSON may be incomplete or invalid.
- **Thread safety**: The class does not employ internal locking. Concurrent read/write access to the same instance from multiple threads can lead to race conditions and inconsistent SARIF output. If shared access is needed, external synchronization (e.g., locking) must be applied.
- **Validation**: The formatter does not automatically validate that the populated model conforms to a specific SARIF schema version. Callers should ensure that values such as `ColumnKind`, `Version`, and `Schema` are compatible; otherwise downstream SARIF consumers may reject the log.
- **Collections**: When assigning new lists to `Runs`, `Invocations`, `Results`, or `Rules`, previous contents are replaced. To incrementally add items, retrieve the existing list and modify it, or instantiate a new list and assign it back.
